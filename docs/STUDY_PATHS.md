# Study paths

The complete system is designed to be used selectively rather than read linearly.

## Seven-day emergency path

1. Complete the Top 100 diagnostic.
2. Score yourself using the readiness rubric.
3. Select only the highest-risk Java, DSA, Spring Boot, security, and SQL topics.
4. Practise answers aloud.
5. Run one production-debugging exercise.
6. Complete one scored mixed mock.
7. Use the final day only for revision and delivery practice.

**Expected outcome:** one priority sheet, thirty spoken answers, and one scored mock.

## Fourteen-day structured path

- Days 1–4: diagnostic, DSA, Core Java, concurrency, JVM, and exceptions.
- Days 5–8: Spring Core, REST, transactions, JPA, testing, and security.
- Days 9–10: SQL correctness, indexes, execution plans, and deadlocks.
- Days 11–12: system design and production debugging.
- Days 13–14: two scored mocks and targeted answer repair.

**Expected outcome:** two scored mocks and a ranked weakness list.

## Thirty-day deep path

- Week 1: DSA and Java backend foundations.
- Week 2: Spring Boot, security, transactions, JPA, and testing.
- Week 3: SQL, architecture, diagrams, and companion-project discussion.
- Week 4: production incidents, take-home practice, and four scored mocks.

**Expected outcome:** solved problems, project stories, SQL evidence, architecture explanations, and measurable mock improvement.

## Core usage rule

Every study session should end with visible evidence:

- a solved problem;
- a spoken answer;
- a diagram explained from memory;
- an incident investigation;
- a query-plan comparison;
- a scored mock or scorecard.
